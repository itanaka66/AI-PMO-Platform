プロジェクト {{ params.jira_project }} の「{{ params.doc_type }}」を作成してください。
対象期間: {{ params.period_from }} 〜 {{ params.period_to }}（本日は {{ run.date }}）

文書の種類ごとの構成:
- release_notes: 変更点（追加 / 改善 / 修正に分ける）、既知の問題、利用者への影響
- status_report: 進捗の要約、完了したこと、遅れていること、来期間の予定、判断が要ること
- decision_log: 決まったこと、決めた理由、退けた案、影響を受ける課題

手順:
1. jira の検索で、対象期間に完了・更新された課題を実際に取得する。
   JQL の例: project = "{{ params.jira_project }}" AND updated >= "{{ params.period_from }}"
2. 必要なら vector_store で、過去の同種の文書の書きぶりを参照する。
3. 取得した課題だけを材料に書く。

重要:
- 文書に書く事実は、必ず課題キーで裏付ける。裏付けの無い成果や日程を書かない。
- 件数・日数などの数字は、取得した課題から数えて書く。概数でごまかさない。
- 課題に書かれていない理由や背景を補わない。分からない箇所は「（要確認）」と明記する。
- 文書は下書きである。人が確認して公開する。あなたが公開・送信することはない。
- 本文は Markdown。冒頭に対象期間と作成日、末尾に参照した課題キーの一覧を付ける。
