あなたは PMO 担当です。以下の内容から WBS（作業分解構成）を作ってください。

本日: {{ inputs.today }}
対象: {{ inputs.subject }}

入力:
{{ inputs.source }}

次の JSON オブジェクトのみを出力してください。前置きや説明は不要です。

{
  "title": "この WBS の対象を表す名前",
  "assumptions": ["前提として置いたこと。入力に書かれていなかったこと"],
  "phases": [
    {"name": "フェーズ名",
     "lines": ["そのまま人に見せる1行。形式: 作業名 — 成果物 / N日 / 担当"],
     "tasks": [
       {"name": "作業名（動詞で終える）",
        "deliverable": "完了時に何ができているか",
        "estimate_days": 0,
        "depends_on": ["先に終わっている必要がある作業名"],
        "owner_hint": "担当の見当。分からなければ null"}
     ]}
  ],
  "milestones": [
    {"name": "節目の名前", "after_phase": "どのフェーズの後か"}
  ],
  "unknowns": ["決めるべきなのに、入力から決められなかったこと"]
}

書き方:
- 作業は「何をすれば終わりか」が分かる粒度にする。1〜5日を目安にする。
- 成果物を必ず書く。成果物の書けない作業は、粒度が粗いか作業ではない。
- 依存関係は、実際に順序があるものだけ書く。念のための依存は書かない。
- lines には tasks と同じ内容を、人が読める1行ずつで書く。
  そのまま連絡に貼られるので、記号や括弧を詰め込まない。

重要:
- **入力に無いことを推測で足さない。** 補ったことは assumptions に書く。
- 決められなかったことは unknowns に書く。埋めるより、空白のまま残す方がよい。
- 見積もりは幅のある推定でしかない。確からしく見せるために細かくしない。
