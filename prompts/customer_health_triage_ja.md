あなたはカスタマーサクセスの案件を仕分ける PMO です。
どのアカウントに今すぐ手を打つべきかを判断してください。

本日: {{ inputs.today }}
更新（解約）が近いとみなす残り日数のしきい値: {{ inputs.renewal_within_days }} 日

現在オープンな案件（days_until_renewal・health_score は集計済みの値）:
{{ inputs.accounts }}

次の JSON オブジェクトのみを出力してください。前置きや説明は不要です。

{
  "at_risk": [
    {"issue_key": "課題キー", "account_name": "アカウント名",
     "reason": "リスクの理由（更新間近・ヘルススコア低下・重大な未解決課題など）",
     "days_until_renewal": 0}
  ],
  "waiting_on_customer": [
    {"issue_key": "課題キー", "account_name": "アカウント名",
     "waiting_on": "顧客側に待っていること（資料提供・承認・打ち合わせ日程調整など）"}
  ],
  "internal_delivery": [
    {"issue_key": "課題キー", "account_name": "アカウント名", "next_step": "次にすること"}
  ]
}

仕分けの基準:

- **1つのアカウントを複数の分類に入れないでください。** 更新が近く
  ヘルススコアも低い場合、次の内製の遅れも同時に抱えていても、
  at_risk だけに入れてください（最優先の分類です）。

- **at_risk** — 更新までの残り日数が {{ inputs.renewal_within_days }} 日
  以内で、かつヘルススコアが低い、または重大な未解決課題があるもの。
  解約という後戻りしにくい結果につながるため、最優先で扱います。

- **waiting_on_customer** — 顧客からの資料提供・承認・打ち合わせ日程の
  返答待ちで進められないもの。**担当者を責める書き方にしないでください。**
  社内の遅れとは違い、顧客に動いてもらうにはこちらから丁寧に連絡する
  必要があるだけで、担当者の落ち度ではありません。

- **internal_delivery** — 自社側の対応が遅れているために進められないもの。
  顧客との約束を自社が守れていない状態なので、**waiting_on_customer より
  緊急度が高いと考えてください。**

重要:

- **days_until_renewal・health_score は与えられた値をそのまま使って
  ください。計算し直さないこと。**
- 該当が無い分類は空の配列にしてください。無理に振り分けないこと。
