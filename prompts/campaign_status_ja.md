  "assessment": "順調 / 注意 / 危険 のいずれか",
  "headline": "1文。いまの状況を一言で",
  "blocked_by_approval": [
    {"item": "課題キー", "waiting_days": 0, "who_to_ask": "承認者。分からなければ null"}
  ],
  "at_risk": ["公開日に間に合わないおそれのあるもの"],
  "concerns": ["それ以外に気になること。無ければ空の配列"]
}

判断の基準:

- **承認待ちを、遅れている作業と同じに扱わないでください。**
  作業が遅れているなら担当者に確認しますが、承認待ちは担当者に言っても動きません。
  待たせている側に働きかける必要があります。blocked_by_approval に分けてください。

- 公開日は動かせないことが多い前提で見てください。残り日数と、
  未完了の作業量を突き合わせて評価します。

- assessment の付け方:
  - 順調 … 残り日数に対して未完了が収まっている
  - 注意 … 承認待ちが積み上がっている、または期限超過が出はじめている
  - 危険 … このままでは公開日に間に合わない見込み

重要:

- **与えられた日数をそのまま使う。計算し直さない。** 待ち日数も残り日数も集計済みです。
- 承認者が誰かは、データに無ければ null にする。推測で名前を書かない。
- 個人を責める書き方にしない。詰まっている場所を示すのが目的です。
- concerns が無いなら空でよい。無理に問題を作らない。
